## Compiler failures

No compiler/linker process crashes or backend/SPIR-V validation failures occurred
in the final 1,024 attempts. The compilation failures are rejected C++ ports or
explicit shader limitations, including seven dynamic global initializers at
each optimization level. Five `-O1` attempts diagnose mixed-width local byte
aggregates; the other `-O1` failures are mostly shared with `-O0`/`-O2`.

The driver now passes the requested optimization level to the SPIR-V backend.
At `-O0`, this prevents backend loop-strength reduction from creating byte-pointer
loop cursors that logical SPIR-V cannot represent. Whole-object zero fills use
a typed null store. Byte-offset access chains can advance across C-array
elements, and vector loads spanning scalar array elements are reconstructed
from scalar loads. Merge instructions are emitted immediately before their
branches, and the structurizer gives nested selections merge blocks dominated
by their headers. The feature suite includes regression cases for each path.

At `-O2`, sine/cosine results now use the input float type, and loop invariant
code motion keeps convergence tokens in their defining blocks. These changes
resolve the previous four compiler failures. Remaining compilation failures
primarily come from untranslated GLSL constructs and unsupported dynamic global
initialization.

## Porting limitations

Other failures include GLSL array declaration/constructor syntax, writable
swizzles, matrix column indexing and mixed scalar/matrix operators, source
`uniform` declarations, dynamic global initialization, and helper/signature
translation. Source warnings also expose unsequenced expressions and possibly
uninitialized values. Compilation alone cannot establish their semantics.

These require a more complete GLSL parser and explicit semantic adaptation; they
must not all be classified as compiler bugs. The compatibility library does not
silently replace unsupported operations with stub results. Nonzero/dynamic
`texelFetch` LOD remains unsupported by the port's load mapping.

## Complete trig coverage

The native compiler now implements all 15 angle/trig operations in
[GLSL.std.450](https://registry.khronos.org/SPIR-V/specs/unified1/GLSL.std.450.html):
`radians`, `degrees`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `sinh`, `cosh`,
`tanh`, `asinh`, `acosh`, `atanh`, and `atan2(y, x)`.

They support scalar, C-array and homogeneous-record overloads, shader 16-/32-bit
floating components, and host float/double math. Unsupported shader double trig
has a direct diagnostic. Native functions remain non-constexpr. Inverse
hyperbolic lowering also fixes the backend's GLSL extended-instruction set
selection rather than misinterpreting the opcode as an OpenCL instruction.
